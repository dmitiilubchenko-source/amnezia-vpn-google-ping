# Исправления после проверки v5

19 октября 2026 года. Основа: тег `google-ping-v5-5.0.3.0`, коммит `ef4516b82d95779d7c24853544f4d61adc3e4256`. Ветка изменений: `codex/fix-premium-benchmark-recovery`.

Windows-сборка v5.2 подготовлена к отдельному релизу. Клиент и служба собраны с MSVC 14.44.35207, Windows SDK 10.0.26100.0, Qt 6.10.0, Conan 2.33.0, CMake 4.4.4 и Ninja. Три набора Windows-тестов прошли: `TestPremiumLatency` — 16, `TestPremiumBenchmark` — 36, `TestGatewayRequestDeadline` — 5 passed; ошибок и пропусков нет. ICMP-проверки loopback IPv4/IPv6/DNS выполнялись нативно на Windows. Полная сборка также проверила интеграцию изменённых C++-файлов.

Фактическая QML-страница отрисована отдельно в Qt 6.10 на Windows с тестовыми контроллерами: спидометр виден в пределах окна, доступен и при нажатии вызывает `checkAll` ровно один раз. Получен снимок `preview-test-data.png`; числа на нём вымышленные. Подпись интерфейса обновлена до v5.2.

Изменения:

- При обрыве туннеля в ожидании маршрута или во время замера с переключением стран выполняется попытка возврата к исходной стране, протоколу и состоянию подключения. Ручная смена страны/протокола и режим «Текущая» не вызывают принудительного возврата.
- Запрос конфигурации ограничен общим сроком 60 секунд, включая поиск резервных API и их проверку. По истечении срока активные сетевые ответы отменяются до завершения future, а отложенные продолжения не возобновляют запросы. Контроллер дополнительно имеет защитный срок 65 секунд. После тайм-аута показано сообщение о ручном выборе исходной страны и переподключении. Новая проверка не начинается, пока backend ещё держит незавершённый запрос.
- Невозможность выполнить ICMP-запрос возвращает `pingError`; сетевые тайм-ауты и ICMP-ошибки доставки остаются наблюдаемыми пропусками.
- Устаревание сохранённых результатов пересчитывается с уведомлением интерфейса раз в минуту.
- Добавлена одна иконка спидометра для пинга известных серверов: 3 ICMP-запроса, до четырёх серверов параллельно, без смены VPN и запросов новых конфигураций. У неизвестного/устаревшего адреса отображается «—». Проверка работает и с активным VPN по текущему маршруту. Кнопки «5» у каждой страны удалены.
- В Git добавлена инструкция `BUILD-GOOGLE-PING.md`. Исправлено исключавшее её правило `.gitignore`. В инструкции используются реальные каталоги CTest. Windows-сценарий сборки запускает три набора тестов и завершается ошибкой, если они не прошли.
- Добавлена поддержка переносного MSVC/SDK. Исправлено исключение `main.cpp` из тестовой библиотеки при работе через junction. Проверка кодов возврата в Windows-сценарии учитывает и отрицательные значения, чтобы установка файлов пакета не начиналась после ошибки компиляции.

Первичная проверка через WSL:

```sh
cmake -S tools/benchmark-tests -B .cache/benchmark-test-build -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build .cache/benchmark-test-build --parallel 4
ctest --test-dir .cache/benchmark-test-build --output-on-failure
```

Среда: Ubuntu 24.04 в WSL, GCC 13.3.0, Qt 6.4.2, Debug. Оба набора прошли после добавления общей кнопки пинга: `TestPremiumBenchmark` — 34 passed; `TestGatewayRequestDeadline` — 5 passed; failed/skipped — 0. В QTest эти числа включают init/cleanup и строки тестовых данных.

Новые сценарии проверяют обрыв при измерении и ожидании маршрута, возврат к исходно отключённому состоянию, сохранение ручной смены протокола, отсутствие переключений в режиме «Текущая», ограниченное ожидание зависшей конфигурации/восстановления, запрет повторного старта при незавершённом запросе, игнорирование поздних результатов и отмену активных/поздних резервных сетевых ответов.

Проверены синтаксис PowerShell-сценария, XML русских переводов и `git diff --check`.

После изменения общей кнопки синтаксис QML-страницы проверен штатным `qmlformat` из Qt 6.4.2. Отформатированная копия записана отдельно; исходная разметка не переформатировалась автоматически.

Общая кнопка использует уже существующий трёхзапросный ICMP-модуль и очередь максимум из четырёх проб. Новый отдельный замер через переключение стран удалён.

Ограничения: полный перебор стран с переподключениями на реальной подписке не запускался. Выполнена отдельная диагностика без записи профиля и без переподключений: девять сохранённых адресов не ответили на три ICMP-запроса каждый; Google через текущий интерфейс AmneziaVPN ответил трижды за 132–139 мс. Это не доказывает недоступность VPN-серверов: ICMP может фильтроваться. Текущая программа, установленная служба и маршруты не менялись. v5.2 выпускается отдельным тегом `google-ping-v5.2-5.0.3.0`; прежняя v5 сохранена.

Для запуска завершите старый клиент через меню значка в трее и откройте EXE из папки v5.2. Спидометр расположен справа от «Страны для подключения». При включённом VPN измерения идут по текущему маршруту; неизвестные адреса обозначаются «—». Предыдущие журналы `live-test.json` и `windows-ping.txt` из опубликованного v5 не используются как проверка новых правок.

## Дополнения v5.2 по журналу пользователя

- Исправлена гонка очереди: старый статус Disconnected до фактического начала openConnectionRequested не завершает новую попытку как connectionError. Регрессионный тест использует асинхронный запуск подключения и старое уведомление.
- Предел ожидания подключения увеличен с 35 до 90 секунд. Отдельный тест удерживает подключение 36 секунд, затем завершает его успешно и проверяет возврат к исходной стране.
- ISO/TextDate и отсутствующая или некорректная дата службы не блокируют успешную обработку статуса connected. Четыре тестовых случая выполняются без подключения к службе.
- Быстрый пинг отличает ошибки Windows API от отсутствия сетевого ICMP-ответа. Интерфейс показывает код ошибки, число ответивших/известных/неизвестных адресов и поясняет, что блокировка ICMP совместима с работающим VPN. Диагностические строки ServerPing не содержат адресов, ключей и идентификаторов подписок.
- В стартовый журнал добавлен явный маркер Google Ping fork UI v5.2.
